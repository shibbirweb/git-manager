## User page: usage/Tabs-and-Tab-Limit.md (outline)

1. Tabs come back after a restart
   - Each folder or workspace remembers its file tabs: order, the tab on screen, pinned tabs, preview (italic) tabs, and where the caret and scroll were.
   - Also when you open the same folder or workspace again later (Open Recent).
   - A file loads only when you first show its tab, so 30 restored tabs cost almost nothing.
   - Files that were deleted or moved are skipped. Up to 50 tabs per workspace are kept, for the 30 workspaces used last.
   - Only file tabs come back; commit, history, branches and terminal tabs do not.
   - Unsaved edits are not kept: save before quitting.
   - Switch: Settings > Editor > Tabs > Reopen tabs on start (on by default). Off, nothing is saved or restored.
2. Reopen Closed Tab
   - Shift+Cmd+T or File > Reopen Closed Tab (also in the Command Palette).
   - Press it again to go further back: the last 20 closed tabs are kept while the app runs (not across restarts).
   - The tab returns at its old place in the strip, with its caret and scroll. Commit, history and branches tabs come back too; terminal tabs cannot (their shell has stopped).
   - Tabs of files that no longer exist are skipped. Tabs closed with the workspace are not offered in the next workspace.
   - A reopened preview tab comes back as a normal tab.
3. Pin a tab
   - Right-click a tab > Pin Tab (Unpin Tab), or Window > Pin Tab (Command Palette: "Window: Pin Tab").
   - A pinned tab shows a small pin after its name. The tab limit never closes it. Pinning a preview tab also keeps it open.
   - Close, Close Others and Close All still close pinned tabs (unchanged).
   - Explain the difference from Keep Open (double-click on an italic preview tab).
4. Tab limit (Settings > Editor > Tabs > Tab limit)
   - No limit (default), Single tab, or Limit with "Most file tabs" (2 to 100, 10 when you first pick it).
   - Single tab: opening a file replaces the tab on screen, for people who want one file at a time.
   - Limit: past the number, opening a file closes the file tab you used least recently.
   - Never closed: tabs with unsaved changes, pinned tabs, the file you just opened. When only those are left the strip goes over the limit until you save or close something.
   - Only file tabs count; commit, history, branches and terminal tabs neither count nor close.
   - The limit acts when a file opens (or a closed tab reopens), not when you switch tabs or change the setting.
   - Closed tabs go to Reopen Closed Tab.

## User page: usage/Auto-Save.md (outline)

1. Auto save (Settings > Editor > Saving > Auto save), like VS Code's files.autoSave
   - Off (default): only Cmd+S, File > Save and Save All.
   - After a delay: a pause after the last edit, Delay in milliseconds (100 to 60000, default 1000).
   - On focus change: when the editor loses focus: clicking another tab, the Files panel, another panel, or switching to another app.
   - What is never auto saved: conflicted files (git lists them as conflicted; save them by hand or use Mark as Resolved), a file open in the merge tool, binary or too large files, files that failed to load. There are no untitled buffers in the app.
   - Auto save is quiet: no "Saved" toast. Errors still show.
   - Saving still refreshes the Changes list, blame and change markers as Cmd+S does.
2. Clean-ups on save (each a switch, all off by default)
   - Trim trailing whitespace: spaces and tabs at line ends. Markdown keeps two or more spaces at the end of a text line (a hard line break).
   - Insert final newline: adds a newline at the end when missing (not to an empty file).
   - Trim final newlines: removes blank lines after the last line of text, leaving one newline.
   - They run on every save: Cmd+S, Save All, auto save and saves from the MCP tools. Mark as Resolved does not run them.
   - One undo (Cmd+Z) brings the text back as it was before the clean-up; the caret stays on its text.
   - During an auto save the lines with a caret are left alone, so the space you just typed stays (VS Code does the same).

## Settings page lines (usage/Settings.md, Editor section)

- Tabs > Reopen tabs on start: open the file tabs a folder or workspace had last time. Default on. `reopenTabsOnStart`.
- Tabs > Tab limit: No limit / Single tab / Limit. Default No limit. `tabLimit` (0 no limit, 1 single tab, 2 to 100 a number).
- Tabs > Most file tabs (with Limit): 2 to 100. Part of `tabLimit`.
- Saving > Auto save: Off / After a delay / On focus change. Default Off. `autoSave` ("off", "afterDelay", "onFocusChange").
- Saving > Delay (After a delay): 100 to 60000 ms. Default 1000. `autoSaveDelayMs`.
- Saving > Trim trailing whitespace. Default off. `trimTrailingWhitespace`.
- Saving > Insert final newline. Default off. `insertFinalNewline`.
- Saving > Trim final newlines. Default off. `trimFinalNewlines`.
- state.json gains `openTabs`: `{ "<workspace id>": { "tabs": [{ "path", "preview", "pinned", "position": { "line", "column", "topLine" } }], "active" } }` (Settings-Files.md). Workspace id is the workspace file path, or the folder roots joined by a newline.

## Developer chapter: developer/How-the-Tab-Session-Works.md (outline)

- Why: people expect their tabs back (VS Code, JetBrains); some want one file at a time; Shift+Cmd+T is muscle memory. Memory is a feature, so restoring must not load 50 files.
- How (mermaid ideas):
  - sequence: App start -> settings.init (state.json openTabs) -> repoStore.replaceWorkspace -> restoreTabs -> api.filesExist -> tabs set, active one awake, others in dormantTabs -> Workspace.svelte mounts FileView only for awake tabs -> openFile/activate wakes a tab -> FileView createEditor takes the pending position.
  - flow: tab change or caret move -> FileView notePosition (500 ms debounce, scroll observer) -> repoStore.noteTabPosition -> scheduleTabsSave (1 s) -> tabSessionOf -> sameTabSession? -> settings.rememberTabs -> settings.save (200 ms) -> state.json.
  - flow: openFile (new tab) -> openTab -> withTabLimit -> tabsToEvict (LRU, skips dirty, pinned, kept, pseudo tabs) -> closeTabs -> applyTabs -> rememberClosedTabs (stack) + tabsChanged (use stamp, wake, prune).
- Where the code lives:
  - `src/lib/stores/tabSession.ts`: TabPosition, SavedTabSession, parse/validate (absolute paths, caps 50 tabs, 30 workspaces), tabSessionOf, restorableTabs, withTabSession.
  - `src/lib/stores/closedTabs.ts`: stack (cap 20, newest last, path dedupe), popClosedTab, updateClosedPosition, reopenAt.
  - `src/lib/stores/tabLimit.ts`: pickTabLimit, tabsToEvict.
  - `src/lib/stores/tabs.ts`: FileTab.pinned, setTabPinned.
  - `src/lib/stores/repo.svelte.ts`: closedTabs, dormantTabs, tabUse, tabPositions, pendingPositions, restoreTabs, reopenClosedTab, withTabLimit, rememberClosedTabs, tabsChanged, noteTabPosition, takePendingPosition, saveTabSession, resetTabSession (teardown saves first).
  - `src/lib/stores/settingsData.ts` / `settings.svelte.ts`: preferences and `openTabs` state, `rememberTabs`.
  - `src/lib/views/Workspace.svelte`: `{:else if !repoStore.isDormant(tab.path)}`.
  - `src/lib/views/files/FileView.svelte`: notePosition, schedulePosition, restorePosition, sessionExtension.
  - `src/lib/views/EditorTabs.svelte`: Pin Tab / Unpin Tab item, pin icon (`pin` in `src/lib/ui/icons.ts`).
  - Menu: `file.reopenClosedTab`, `window.pinTab` in menuIds.ts, menuSpec.ts, menuState.ts (closedTabCount, activeTabPinned inputs), menuActions.ts, appMenu.svelte.ts, registry.ts disabled reasons.
- Design decisions:
  - "Pin" here is a new sticky flag (`pinned`), separate from the old preview "Keep Open"; the code's `pinTab`/`pinFile` still mean Keep Open.
  - Only file tabs are saved and counted: pseudo tabs carry state a restart cannot restore (terminal) or are opened on purpose.
  - Positions are lines, not offsets, so a file changed outside the app still lands near the right place; the top line is measured only while the editor is visible (hidden editors measure 0).
  - The limit runs only when a new tab is added, never on tab switches, so switching never closes tabs.
  - Eviction never asks: only clean, unpinned tabs are closed, and they go to the closed stack.
  - Closed stack is memory only and dropped with the workspace; entries are checked with filesExist before reopening.
  - Reopened tabs come back as normal (not preview) tabs.
  - Teardown saves the session before clearing tabs, so Close Folder and opening another folder keep the tabs for next time.
  - A settings.json that failed to parse is untouched (same writableConfigs path); state.json likewise.
- Tests: tabSession.test.ts, closedTabs.test.ts, tabLimit.test.ts, tabs.test.ts (setTabPinned), settingsData.test.ts (prefs, openTabs), menuState.test.ts, menuSpec.test.ts.
- Keeping in sync: a new tab kind must decide if it is a file tab (pseudoTabs.ts) and whether it can be reopened (rememberClosedTabs skips terminals); new preferences go in settingsData.ts, settings.svelte.ts and SettingsDialog.svelte.

## Developer chapter: developer/How-Auto-Save-Works.md (outline)

- Why: VS Code users expect files.autoSave and the save clean-ups.
- How (mermaid ideas):
  - state diagram of triggers: edit -> scheduleAutoSave (afterDelay timer) -> autoSave("delay"); editor blur / window blur / tab hidden (isActive true -> false) -> autoSave("focus") -> shouldAutoSave guard -> save({ quiet, auto }) -> applySaveCleanup -> writeWorktreeFile -> refreshRepoStatus; still dirty -> schedule again.
  - save pipeline: richRef.flush -> saveCleanupTransaction (one transaction, isolateHistory "full") -> snapshot -> write -> baseline.
- Where: `src/lib/editor/autoSave.ts` (shouldAutoSave, AUTO_SAVE_DELAY_RANGE), `src/lib/editor/saveCleanup.ts` (saveCleanupChanges on a LineSource, caretLines, saveCleanupTransaction), FileView.svelte blocks (applySaveCleanup, autoSave, scheduleAutoSave, the two $effects, sessionExtension observers), settingsData.ts (AutoSaveMode).
- Design decisions:
  - Conflicted files (tone "conflict") and the merge tool's file are never auto saved: their resolution is deliberate, and a write would change the file under the merge tool.
  - Auto save is quiet (no toast) but uses the same save(), so blame, change markers and the Changes list refresh as with Cmd+S.
  - A failed auto save is not retried on a timer, so a read-only file cannot toast every second.
  - Clean-ups skip caret lines only for auto saves (VS Code does the same), so typing "foo " then pausing keeps the space.
  - Markdown hard breaks: a run of 2+ spaces (no tabs) after text is kept.
  - The clean-up is one transaction with isolateHistory "full", so it never merges with typing in the undo history; carets map through it (a caret at the end stays before the added newline).
  - Clean-ups also run on Cmd+S of a clean file (the save still happens); Mark as Resolved does not run them.
- Tests: saveCleanup.test.ts (each option, Markdown, combinations, keepLines, one undo step, caret mapping), autoSave.test.ts.
