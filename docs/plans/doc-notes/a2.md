## User page outline: usage/Custom-Keyboard-Shortcuts.md

1. What it is: every command of the menu bar and the Command Palette can get other keys, like VS Code's Keyboard Shortcuts or JetBrains' Keymap.
2. Open it: Settings (Cmd+,) > Keyboard Shortcuts; Command Palette "Preferences: Open Keyboard Shortcuts"; Help > Keyboard Shortcuts > Change Shortcuts.
3. The list: each row is "Category: Command" (same names as the Command Palette) and its keys. "Changed" badge on keys you changed (hover shows the default). "Conflict" badge when another command has the same keys.
4. Search: type words of the name or category ("git push", "current file"), a command id (`git.file.add`) or keys as written (⇧⌘P). "Record Keys" button: press keys instead of typing to find what uses them; Backspace clears, Esc stops. "Changed only" checkbox. Count of commands.
5. Change keys: click the keys (or "None") of a row, press the new keys. Enter or Save keeps them, Esc or Cancel stops. Needs Cmd, Ctrl or Option (Alt); F1 to F24 work alone.
6. Conflicts: when the keys are taken, the row says "Also used by ..." with Keep Both (both keep them; inside an editor the editor command wins, elsewhere the first in menu order) or Replace (the other command loses its keys).
7. Reserved keys: Cmd+Q, Cmd+H, Option+Cmd+H, Cmd+M, Cmd+Tab, Cmd+` , Cmd+Space, Ctrl+Cmd+F, Ctrl+Cmd+Q, Shift+Cmd+3/4/5, Cmd+X/C/V on macOS; Alt+F4, Alt+Tab, Ctrl+Alt+Delete, Super+L (Windows), Ctrl+X/C/V elsewhere. The row says why.
8. Remove (x button) leaves a command without keys; Reset (arrow button) brings the default back; Reset All (asks first) restores every default. Settings > Reset to Defaults resets them too.
9. Double Shift (Search Everywhere) is fixed and shown at the top of the page; Search Everywhere can get extra keys.
10. Where custom keys work: the menu bar shows them; they work in the window, in text fields, in editors (an editor command's new key works in every editor, the merge tool too; a window command's custom key also works while typing in an editor) and from a terminal (see 11).
11. In a terminal: the shell keeps plain keys, Ctrl+letter, Alt+letter (and Ctrl+Alt, which is AltGr, on Windows and Linux). Keys with Cmd, Ctrl+Shift or Super reach the app. So Ctrl+Shift+P opens the Command Palette from a terminal on Windows and Linux. The terminal's own keys (Cmd+K clear, Cmd+C copy, Ctrl+Shift+C/V) come first.
12. settings.json: `"keybindings": { "git.push": "CmdOrCtrl+Shift+U", "view.log": null }`. Unknown command ids and keys that do not parse are dropped on load; the file is never rewritten when it failed to parse.

## Developer chapter outline: developer/How-Custom-Shortcuts-Work.md

- Why: users come from VS Code and JetBrains with their own keys; shortcuts were hard-coded in four places (menuSpec accelerators, workspaceShortcuts.ts, CodeMirror keymaps, terminal/keys.ts), so they had to come from one list.
- How (mermaid ideas):
  1. Flowchart: settings.json `keybindings` -> `pickKeybindings` (settingsData) -> `settings.keybindings` ($state.raw) -> `usableOverrides(platform)` (drops reserved, normalizes to menu notation) -> four consumers: appMenu (setAccelerator per changed item), Workspace window handler (`windowCommand`), editors (`editorKeyPlan` -> `commandKeys` compartment), terminal (`terminalAppKeys` -> `appKeys` context).
  2. Sequence for one key press on macOS: keydown -> CodeMirror keymaps (custom plan at Prec.highest, then code/default/find keymaps) -> if not prevented, window handler (`windowCommand`) -> if not prevented, native menu key equivalent.
  3. Flowchart for recording: keydown in recorder -> `recordKeys` -> problem? (reserved, needs modifier, cannot write) -> `commandsWithKeys` conflicts -> Keep Both (`withShortcut`) or Replace (`replaceShortcut`).
- Where the code lives:
  - `src/lib/commands/shortcutSettings.ts`: validation (`pickKeybindings`), reserved keys (`reservedReason`, `shortcutProblem`), `usableOverrides`, `recordKeys`, edits (`withShortcut`, `withoutOverride`, `replaceShortcut`), conflicts (`commandsWithKeys`, `shortcutConflicts`), list rows and search (`shortcutRows`).
  - `src/lib/commands/keybinding.ts`: new `bindingId`, `acceleratorId`, `codeMirrorKey`.
  - `src/lib/commands/registry.ts`: `menuAccelerators`, new app command `settings.keyboardShortcuts` (Preferences: Open Keyboard Shortcuts), `WINDOW_DEFAULTS` (view.changes answers to Shift+Cmd+G from the window, which the menu leaves off).
  - `src/lib/commands/commandRuntime.ts`: `shortcutOverrides()` (was the empty hook), `windowKeys()`, `terminalAppKeySet()`, `shortcutFor()`, `usesDefaultKeys()`.
  - `src/lib/commands/editorKeyPlan.ts` (pure) and `src/lib/editor/commandKeys.ts` (CodeMirror compartment + view registry, wired in `setup.ts` and `App.svelte`).
  - `src/lib/views/workspaceShortcuts.ts`: `WINDOW_COMMANDS` map and `windowCommand` (registry based) replace the hard-coded key checks; `Workspace.svelte` runs it; `searchTabs.ts` / `FileSearch.svelte` and `QuickOpen.svelte` match the effective keys too.
  - `src/lib/terminal/keys.ts`: `shellOwns`, `terminalAppKeys`, `appKeys` in the context; `TerminalView.svelte` passes it.
  - `src/lib/menu/appMenu.svelte.ts`: keeps every action item's objects, follows `settings.keybindings` with one effect and calls `setAccelerator` only for items whose key changed.
  - `src/lib/views/settings/KeyboardShortcuts.svelte` (UI), section "keyboard" in `SettingsDialog.svelte` and `SETTINGS_SECTIONS` (so MCP `open_settings` can open it).
  - Help: `help/shortcuts.ts` takes custom keys; `ShortcutsDialog.svelte` has Change Shortcuts. MCP `list_menu_commands` reports custom accelerators.
  - Local save keys: `FileView.svelte` (Mod-s) and `MarkdownPreview.svelte` skip Cmd+S when Save has a custom key; `App.svelte` skips Cmd+, when Settings has one.
- Design decisions:
  - Overrides only store what differs (`commandId -> accelerator | null`); choosing the default again drops the entry, so a later default change still reaches the user.
  - One key per command (VS Code allows several; kept simple).
  - The native menu is built with the menu's own keys, then custom ones are applied with `setAccelerator`, so a key the native parser refuses only leaves one item without a key instead of failing the whole menu bar. One effect per change, only changed items touched (memory and IPC stay low).
  - Window handler runs: the built-in window commands, app commands (no menu item) and any global command with a custom key. Other default menu keys stay with the native menu (unchanged behavior, works on the welcome screen).
  - Editor: CodeMirror cannot "skip" a lower keymap, so the plan binds new keys, swallows freed default keys (`blocked`), and hands freed keys to the window command that now owns them; editor keys win over window keys inside an editor ("Keep Both").
  - Conflicts: any two commands with the same keys (global keys reach editors too); pairs where both keep the default are hidden (Shift+Cmd+G is intentionally Find Previous in editors and Changes elsewhere).
  - Terminal pass-through rule (`shellOwns`): shell keeps plain, Shift, Ctrl+key, Alt+key, AltGr (Ctrl+Alt on Windows/Linux); Ctrl+` passes.
  - Reserved keys per platform; plain keys need a modifier except F1 to F24.
  - Validation: unknown ids and unparsable accelerators dropped on load (`pickKeybindings`, cap 500); reserved/bare keys ignored at use (`usableOverrides`); a settings.json that failed to parse is never overwritten (existing `writableConfigs`).
- Behavior changes to note: window shortcuts now match exactly the registry keys per platform: on macOS Ctrl no longer acts as Cmd (Ctrl+B, Ctrl+P); on Windows/Linux Ctrl+Shift+] / [ no longer switch tabs outside an editor (Ctrl+PageDown / PageUp do, as the menu shows).
- Tests: `shortcutSettings.test.ts`, `editorKeyPlan.test.ts`, new cases in `keybinding.test.ts`, `registry.test.ts`, `terminal/keys.test.ts`, `workspaceShortcuts.test.ts` (now registry based, Windows platform, custom keys), `searchTabs.test.ts`, `help/shortcuts.test.ts`, `settingsData.test.ts`, `mcp/menuCommands.test.ts`.
- Keeping in sync: a new menu item gets custom keys for free; a new hard-coded key handler should use `windowKeys()` / `shortcutFor()` / `usesDefaultKeys()` instead of fixed keys; a new app command goes in `APP_COMMANDS` (and `WINDOW_COMMANDS` if the window runs it).

## Settings reference lines

- `keybindings` (settings.json, object, default `{}`): custom keyboard shortcuts by command id. Value: a menu accelerator such as `"CmdOrCtrl+Shift+U"`, `"Ctrl+``"`, `"Alt+Up"`, `"F5"`, or `null` to remove the default key. Unknown ids and keys that do not parse are dropped. Edited in Settings > Keyboard Shortcuts.
- Settings section id `keyboard` (MCP `open_settings` section enum includes it).
