## User page: usage/Commit-Identity.md (about 400 words)

- What it is: git writes a name and an email into every commit (`user.name`, `user.email`). Explain "global config" (one file for all repositories, `~/.gitconfig`) and "repository config" (`.git/config`, wins over global) on first use.
- Settings > Git > Commit identity, "Name and email" row:
  - **Global** block: Name and Email fields, **Save**; the file path git writes is shown next to "Global" (GIT_CONFIG_GLOBAL when set, else `~/.gitconfig`, or the XDG file when only that exists).
  - **Repository** block: a repository picker when several are open; Name and Email fields whose placeholders show the global values with "(global)"; **Save**; the line "Commits use Name <email>" or the warning "git has no name and email here yet"; **Use Global** (only when the repository has its own values) asks first, then removes them.
  - Leave a field empty and Save to remove that value (git never gets an empty value). Removing a global value asks first ("Remove Global Identity").
  - Light checks: an email needs something@something with no spaces or < >; a name cannot contain < > or line breaks.
- The **Who is committing?** dialog: appears when you commit (Commit button, Cmd+Enter, the row's Commit, the Commit menu items, Git > Current File > Commit File...) in a repository where git has no configured name and email. Fields Name and Email, "Use for": **All repositories (--global)** or **Only <repo>**. **Save and Commit** saves and continues; **Cancel** stops the commit. Starts with whatever is already set (repository first).
- Why we ask: without config git either fails with "Please tell me who you are" or, on a Mac, quietly makes up `you@your-mac.local`.
- Tip: identities from `includeIf` (per folder) count; the dialog only shows when git really has none.

## User page: usage/Commit-Messages.md (about 600 words)

- **Message history**: the clock icon at the top right of the commit message box, Cmd+E in the box (Ctrl+E on Windows and Linux), or Up in an empty box. Lists up to 30 messages, newest first, with their age: your own recent commits in this repository (author email = your user.email, merges left out) and messages you typed but did not commit: a commit that failed, a box you cleared, a message replaced by a template or a history pick, and messages committed from the app. Pick one to put it in the box (the text you had goes into the history). Kept per repository in `~/.gitmanager/state.json` (`commitMessages`).
- Settings > Git > Commit messages > **Message history** switch (on). Off: no clock, no Cmd+E, nothing saved, and replacing a typed message asks first ("Replace Message"). **Clear Saved Messages** (asks first) forgets the saved ones; messages from your commits still show because they come from git.
- **Templates**: the page icon next to the clock opens the Templates menu: your templates by name, **Git Commit Template** (when `commit.template` is set), and **Edit Templates...** (opens Settings > Git). Settings > Git > Templates: **Add Template**, a name and text per template, trash icon deletes (asks first). Names must be unique and not empty.
  - Placeholders: `{branch}` the current branch, `{ticket}` the ticket in the branch name like GM-12 (Jira-style KEY-123; lower-case keys too, except words like release, fix, feature), `{user}` your user.name, `{date}` today like 2026-10-03, `{cursor}` where the caret goes. Example: `feat:[{ticket}] {cursor}` on `feat/GM-12-search` gives `feat:[GM-12] ` with the caret at the end.
- **commit.template**: when git config has `commit.template`, its text fills the empty commit box (after each commit too). Lines starting with `#` are left out (git keeps them with `-F`) and shown as the box's placeholder instead. An untouched template counts as no message: Commit stays disabled until you change it, like git.
- **Subject line guide**: Settings > Git > **Subject line guide** (on): "Subject is N characters; keep it to 72" under the box when the first line is longer than 72 characters. It is only a note; you can still commit.
- Shortcuts: Help > Keyboard Shortcuts has a new "Commit box" section (Commit Cmd+Enter, Message history Cmd+E / Up).

## Developer chapter: developer/How-Commit-Identity-Works.md

- Why: first-run users hit git's raw error; Macs silently auto-detect a bogus email. Settings needs to show and edit both levels.
- How (mermaid sequence): CommitBox / commitRepo -> `ensureIdentity` (identityCheck.ts) -> `get_identity(repoPath)` -> `identity_ready` runs `git -c user.useConfigOnly=true var GIT_COMMITTER_IDENT` and `GIT_AUTHOR_IDENT` -> complete? commit : `gitDialogs.open({ kind: "identity", resolve })` -> IdentityDialog -> `set_identity` (git config --global/--local) -> resolve(true) -> commit.
- Mermaid flowchart for reads: global = git2 Config built from GIT_CONFIG_GLOBAL, or XDG file + ~/.gitconfig (includes followed); local = repo config `open_level(Local)`; readiness = git itself (includes, includeIf, environment like GIT_AUTHOR_NAME and EMAIL).
- Where the code lives: `src-tauri/src/git/identity.rs` (GlobalConfig, read_identity, identity_ready, write_identity, name_error, email_error), `src-tauri/src/commands/identity.rs` (get_identity, set_identity), `src/lib/views/changes/identity.ts` (validation, prefill, label), `identityCheck.ts`, `IdentityDialog.svelte`, `src/lib/views/settings/GitIdentitySettings.svelte`, `gitDialogs.svelte.ts` (kind "identity" with a resolve callback; the dialog resolves false in onDestroy so a replaced dialog never leaves the commit waiting).
- Design decisions:
  - Readiness asks git (`git var` with useConfigOnly) instead of git2: libgit2 opened with `Repository::open` ignores GIT_CONFIG_GLOBAL, and a git2 Config built from files has no repository, so `includeIf "gitdir:"` (a common way to keep a work identity) would not match. This is a read through the CLI; it uses `cli::command` directly so it is not logged in the Git Console.
  - Writes: `git config --global|--local -- key value` (the `--` keeps a value starting with "-" from being read as an option). Empty values are unset with `--unset-all`, only when present (git exits 5 otherwise). Never write an empty value.
  - Validation is light and the same on both sides (Rust is authoritative).
  - The check runs before every commit (two short `git var` runs), no cache, so changing config outside the app is always seen.
- Tests: `git::identity::tests` (8): no identity, global write into its own file, local override and Use Global, name alone not enough, dash values, global include followed, bad values refused, local needs a repository. Test isolation: `GlobalConfig::at(file)` passes GIT_CONFIG_GLOBAL per test and drops identity env vars; the sandbox in `test_support.rs` already points HOME and GIT_CONFIG_GLOBAL away from the user's files. Vitest: `identity.test.ts`.
- Keeping in sync: `Identity`, `IdentityValues`, `IdentityScope` in `types.ts` mirror Rust; the rules in `identity.ts` mirror `name_error` / `email_error`.

## Developer chapter: developer/How-Commit-Messages-Work.md

- Why: JetBrains-style message history and templates; JetBrains Cmd+E.
- How (mermaid): openHistory -> settings.commitMessages[repoRoot] (state.json) + `recent_commit_messages(repoPath, 30)` (git2 revwalk from HEAD, at most 400 commits, author email = user.email any case, no merges, no repeats) -> `mergeHistory` (each message once at its newest time, newest first, cap 30) -> `historyMenuItems` -> contextMenu. Recording: `settings.rememberCommitMessage` from commitRepo (failed and successful commits), commitCurrentFile, CommitBox `onInput` (box cleared) and `replaceMessage` (text replaced).
- Templates flow (mermaid): menu -> `expandTemplate(text, { branch, userName, date })` -> `{ text, cursor }` -> replaceMessage -> caret at cursor. `ticketFromBranch`: strict `[A-Z][A-Z0-9]{1,9}-\d+`, then lower-case `[a-z]{2,10}-\d+` minus a stop list.
- commit.template: `get_commit_template` (git2 `commit.template`, `~/` expanded, relative to the work tree top, max 64 KiB, missing file is None) -> `splitGitTemplate` -> prefilled once per commit cycle by an `$effect` in CommitBox (`CommitDraft.templateChecked`), comments become the placeholder. `CommitDraft.isBlank()` treats the untouched template as empty for Commit, commitPlan, amend (HEAD message replaces it, unchecking restores it) and Undo Last Commit.
- Where: `src-tauri/src/git/messages.rs`, `src-tauri/src/commands/identity.rs` (recent_commit_messages, get_commit_template), `src/lib/views/changes/commitMessages.ts`, `commitTemplates.ts`, `commitMessageMenus.ts`, `commitDraft.svelte.ts`, `CommitBox.svelte`, `src/lib/views/settings/CommitTemplateSettings.svelte`, settings in `settingsData.ts` / `settings.svelte.ts`, shortcuts row in `src/lib/help/shortcuts.ts`.
- Design decisions: history merged by time so terminal commits interleave with app-saved messages; saved messages capped at 30 per repository and 50 repositories (least recently used dropped) to keep state.json small; history off stops recording and the menu; template comments stripped because `-F` uses cleanup "whitespace"; subject guide is a soft note, no blocking; Cmd+E on macOS only (Ctrl+E moves to line end there).
- Tests: Rust `git::messages::tests` (4). Vitest: `commitMessages.test.ts` (7), `commitTemplates.test.ts` (7), `commitMessageMenus.test.ts` (2), settingsData "commit message settings" (3), shortcuts "commit box shortcuts" (1).

## Settings reference lines (developer/Settings-Reference.md)

settings.json:
- `commitMessageHistory` boolean, default `true`: the commit box message history (clock, Cmd+E, Up) and saving uncommitted messages.
- `commitSubjectGuide` boolean, default `true`: note when the subject line passes 72 characters.
- `commitTemplates` array of `{ name, text }`, default `[]`: names trimmed, 1 to 80 characters; text up to 10000 characters; at most 50; malformed entries dropped.

state.json:
- `commitMessages` object, default `{}`: repository root -> array of `{ message, time }` (time in ms), newest first, at most 30 per repository and 50 repositories; blank, duplicate, over 20000 characters or malformed entries dropped.

Not in settings: user.name / user.email live in git config, not in `~/.gitmanager`.
