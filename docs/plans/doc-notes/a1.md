## User page outline: usage/Quick-Open.md

1. What it is: VS Code's Quick Open. One box at the top of the window; what you type first picks the mode.
2. Open it
   - Cmd+P or Edit > Go to File... : find a file.
   - Shift+Cmd+P or View > Command Palette... : run a command. Works on the welcome screen too (commands only).
   - Press Cmd+P or Shift+Cmd+P again while it is open to switch between files and commands (or move down when already there).
3. Find a file
   - Empty box: "Recently opened" files (Back/Forward history, then open tabs). The file on screen is last, so Cmd+P then Enter goes back to the previous file.
   - Typing: recently opened matches first, then "File results" from the workspace index (same index as Search Everywhere).
   - `name:42` or `name:42:5` opens at that line and column.
4. Prefixes (table): `>` commands, `:` go to line, `@` symbols in the file, `#` symbols in the workspace, `?` list of prefixes. Delete the prefix to go back to files.
5. Command Palette
   - Each row: category ("Git", "Git > Current File"), title, a check for toggles that are on, the shortcut.
   - "Recently used" on top (last 20, kept in `~/.gitmanager/state.json`), then all others A to Z.
   - Disabled commands are grey with a short reason ("Needs a text editor", "Open a folder first", "Git is busy"); Enter on one shows the reason in the box.
   - Words match in any order: "push git" finds Git: Push. Initials work: "sc" finds Stash Changes.
   - Command Palette: Clear Recently Used.
6. Go to Line: `:120`, `:120:5` or `:120,5` in the editor the box opened over. Empty `:` shows the current line and the range.
7. Symbols in the file (`@`): functions, classes, methods (indented under their class) and Markdown headings, unsaved edits included. Type to filter.
8. Symbols in the workspace (`#`): same results as the Symbols tab of Search Everywhere.
9. Keys: Up/Down (also Ctrl+N / Ctrl+P), Page Up/Down, Enter, Escape (focus goes back where it was). Cmd+Enter acts like Enter (there is one editor group).
10. Quick Open versus Search Everywhere: double Shift still opens Search Everywhere with its tabs; Shift+Cmd+O still opens its Files tab. The two never open at the same time.

Verify labels in code: placeholder "Search files by name, or type ? for help"; status labels come from `PREFIXES` in `src/lib/quickOpen/quickOpenModel.ts`.

## Developer chapter outline: developer/How-Quick-Open-Works.md

- Why we need it: users coming from VS Code expect Cmd+P / Shift+Cmd+P; every menu command reachable from the keyboard; groundwork for custom keyboard shortcuts.
- How it works
  - mermaid flowchart: key press -> `workspaceShortcuts.ts` ("quickOpen" / "commandPalette") or native menu (Edit > Go to File, View > Command Palette) -> `openQuickOpen(prefix)` in `workspaceActions.ts` -> `quickOpen.open()` captures focus + editor target, blurs -> App.svelte lazy-loads `QuickOpen.svelte` -> `parseQuickOpen(value)` picks mode -> per-mode source.
  - mermaid sequence for files mode: QuickOpen -> `file_search_open` (progress channel) -> `file_search_query` with request ids (stale answers dropped; Rust also cancels older queries through its query sequence) -> retry every 250 ms while indexing -> `file_search_close` on unmount.
  - mermaid for `@`: QuickOpen -> `document_symbols(filePath, text)` (Rust `symbols/outline.rs`, same scanners as the symbol index + Markdown ATX headings, nothing cached) -> JS fuzzy filter.
  - Command registry diagram: `menuSpec.ts` + `APP_COMMANDS` -> `buildCommandSpecs` -> `commandViews(specs, menuState(inputs), inputs, overrides)` -> `paletteList` -> rows; `runCommand` -> `runMenuAction` or workspace shortcut.
- Where the code lives
  - `src/lib/commands/registry.ts` (pure registry, views, disabled reasons, palette ordering), `keybinding.ts` (parse/match/format shortcuts), `fuzzy.ts` (scorer), `recentCommands.ts` (MRU), `commandRuntime.ts` (platform specs cache, current views, `runCommand`).
  - `src/lib/quickOpen/QuickOpen.svelte`, `quickOpenModel.ts` (prefixes, go to line, rows, selection), `quickOpenStore.svelte.ts` (open state, focus and editor capture).
  - Rust: `src-tauri/src/symbols/outline.rs`, command `document_symbols` in `commands/search.rs`.
  - Wiring: `menuIds.ts` (`view.commandPalette`), `menuSpec.ts` (View > Command Palette...), `menuActions.ts`, `workspaceShortcuts.ts`, `workspaceActions.ts` (`openQuickOpen`, blockers), `searchTabs.ts` (Cmd+P inside Search Everywhere still picks Files), `App.svelte`, MCP `appState.ts`/`handlers.ts` (kind "quickOpen" in `get_app_state`/close dialog), `settingsData.ts` (`recentCommands`).
- Design decisions
  - Separate component from Search Everywhere (user asked); shares Rust commands and pure helpers (`fileSearchModel`, `symbolSearchModel`, `popupRows`).
  - Files and workspace symbols matched in Rust (500k-file index); commands (about 170) and one file's symbols (max 5000) matched in JS: a round trip would cost more than the match.
  - Fuzzy scorer: DP over (query letter, target position) with capped gap penalty, running max for far positions, so O(m*n*7); word-start and camelCase bonuses; each query word separately; tiny length penalty breaks ties.
  - Menu state snapshot at open; the editor part comes from the captured editor, so editor commands are enabled even though the popup has the focus; `runCommand` focuses that editor before running.
  - Disabled commands greyed with a reason derived from the same `MenuInputs` (no extra state).
  - Memory: popup lazy-loaded, mounted only while open, `$state.raw` lists, virtualized rows (26 px), only the MRU (20 ids) persisted; `release()` drops the captured EditorView on close.
  - Cmd+P previously opened Search Everywhere's Files tab; now it is VS Code's Quick Open. Shift+Cmd+O keeps the JetBrains Files tab.
  - Shortcut overrides: `effectiveShortcut(spec, overrides)` and `commandForKey`; `shortcutOverrides()` in `commandRuntime.ts` returns `{}` until custom shortcuts land.
- Tests: `commands/registry.test.ts`, `keybinding.test.ts`, `fuzzy.test.ts`, `recentCommands.test.ts`, `quickOpen/quickOpenModel.test.ts`, `settingsData.test.ts` (recentCommands), `workspaceShortcuts.test.ts`, `searchTabs.test.ts`; Rust `symbols::outline::tests` (5).
- Keeping in sync: a new menu item becomes a command automatically; an app action without a menu item goes in `APP_COMMANDS` and `runCommand`; a new `MenuInputs` field may need a line in `disabledReason`.
