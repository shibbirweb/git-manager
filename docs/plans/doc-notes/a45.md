## User page outline: usage/Local-History.md

1. What it is: a safety net beside git. The app keeps a copy of a file's text (a "version") when:
   - you save it in the app (label "Saved"); the first save also keeps the text it replaced ("Before save"),
   - an open file changes outside the app, before the editor reloads it ("Before external change" and "External change"),
   - before Discard (files or selected lines) in Changes ("Before discard"), Rollback ("Before rollback") and File > Revert File with unsaved edits ("Before revert").
   Files over 1 MB are skipped. Explain "discard" and "rollback" briefly (throwing away changes since the last commit).
2. Open it: right-click a tab > Show Local History; Files panel right-click a file > Show Local History; File > Show Local History; Command Palette "Show Local History".
3. The window: versions on the left grouped by Today / Yesterday / date, newest first, time and label (versions kept before a discard, rollback or revert are in the warning color). Arrow keys, Home and End move. The right side is a diff: the version (left) against the current text (right; "Current (unsaved)" when the editor has unsaved edits).
4. Buttons: Revert to This (puts the version in the editor as one change, Undo takes it back; then Save to keep it), Copy (copies the version's text). Escape or the X closes.
5. Deleted files: File > Recently Deleted Files..., or right-click a folder in the Files panel > Show Recently Deleted. Pick a file, pick a version, Restore File writes it back (folders are created). A deleted file's tab menu and git-deleted rows in the Files panel also offer Show Local History.
6. Settings > Editor > Local History: Keep local history (on by default), Keep versions for (1, 3, 7, 14, 30 days; default 7), Size limit (50 MB, 200 MB, 500 MB, 1 GB; default 200 MB), Stored line (versions, files, size on disk) and Clear Local History (asks first, cannot be undone). Each file keeps its newest 50 versions.
7. Where it lives: `~/.gitmanager/local-history`. Not shared, not in git, local to this Mac.

Screenshots:

- `local-history-deleted.png`: Recently Deleted list with two or three files.
- `local-history-settings.png`: Settings > Editor scrolled to the Local History group.

## User page outline: usage/Notifications.md

1. Every message the app shows (info, success, warning, error) is also kept in the bell at the bottom right of the status bar, for this session only (at most 200, gone after a restart).
2. The badge counts unread errors and warnings (red when an error is among them, else amber). Opening the list marks everything read.
3. The list: newest first, kind icon, title, details, time ("just now", "5 min ago", full date on hover) and the message's button (Undo, Open...) while it still works: once, for 2 minutes, or 30 minutes when the button can check that what it acts on is unchanged (Restore's Open does).
4. Clear All empties the list.
5. Do Not Disturb: in the list's header, View > Do Not Disturb, or Settings > Layout > Do not disturb. Only errors pop up; everything else is still listed. The bell shows a crossed-out bell while it is on.
6. View > Notifications (or the Command Palette) opens the list.

## Developer chapter outline: developer/How-Local-History-Works.md

- Why: git only knows committed or staged text; saves, outside edits and discards in between are lost. JetBrains Local History and VS Code Timeline solve this; ours adds Restore for deleted files.
- Storage format (src-tauri/src/local_history/store.rs):
  - `objects/<2 hex>/<38 hex>`: zlib (flate2) of the bytes, named by the git blob id (SHA-1 via `git2::Oid::hash_object`), so identical text is stored once across files and times; reading checks the hash ("damaged" otherwise).
  - `index/<sha1 of the absolute path>.json`: `{ version: 1, path, snapshots: [{ time, label, hash, size }] }`, oldest first, one small file per tracked file (a save reads and writes only it). Note: the task asked for "an index per workspace"; we chose one index per file so the history follows a file across workspaces and a save never rewrites a big index; Recently Deleted filters indexes by folder prefix.
  - Writes are temp file + rename; leftovers `.tmp` are removed by pruning. Unreadable or newer-version indexes are skipped, never deleted.
- Mermaid idea 1 (flowchart): Save in FileView -> `write_worktree_file` (reads old bytes, writes, returns) -> background thread `record_save` -> lock -> Store.record (dedup by newest hash, per-file count and age) -> maybe spawn prune.
- Mermaid idea 2 (sequence): external change: watcher -> status refresh -> FileView.load(quiet) -> `localHistory.noteReload` -> one `local_history_record` call with [beforeExternalChange(editor text), externalChange(read from disk)] -> editor takes disk text.
- Hooks (Rust, no extra IPC): `commands/status.rs` write_worktree_file (Saved, Before save), discard_files (Before discard, tracked and untracked, folders walked up to 300 files and 16 MB per action, skipping .git and symlinks), run_rollback (Before rollback); `commands/lines.rs` Discard Selected Lines (Before discard). Frontend hooks: FileView.load with quiet=true (external change: editor text plus disk text in one call) and FileView.revert (unsaved edits, recorded before dirty is cleared). Destructive snapshots run before the action on the same blocking thread; failures never block the action.
- On/off: `local_history::configure(root, limits)` from `local_history_configure` (App.svelte effect on the three settings). Off by default in the process, so tests and the mergetool window never write to ~/.gitmanager. Limits are clamped in Rust (plan.rs) and in settingsData.ts.
- Pruning (plan.rs, pure): drop snapshots without an object, keep the newest 50 per file younger than N days, then drop the oldest snapshots across files until referenced objects fit the size limit (shared objects count once), delete unreferenced objects. Runs on a background thread at configure (start, settings change) and after writes once 1/20 of the size limit was written or 30 minutes passed; one at a time (atomic flag), under the write lock.
- Memory: nothing cached; every call reads from disk. The window loads one diff at a time and is lazy-imported; DiffView is destroyed on close.
- UI: `src/lib/localHistory/` (localHistoryModel.ts pure + tests, localHistory.svelte.ts store, LocalHistoryDialog.svelte). Revert goes through `fileCommands.replaceText` (FileView `replaceText`, one undoable dispatch, userEvent "input.revert"); if the file is not open it opens it and waits up to 4 s for the editor.
- Commands: local_history_configure, _record, _list, _diff (version vs editor text or disk, via git/diff.rs from_bytes), _restore (refuses when a file exists; only hashes in that file's index), _deleted, _usage, _clear.
- Menu: file.localHistory, file.recentlyDeleted (menuIds, menuSpec, menuState, menuActions, registry disabled reason); tab menu (EditorTabs.svelte), Files panel menu (FileExplorer.svelte). The window blocks workspace shortcuts (workspaceActions.ts).
- Tests: Rust local_history/tests.rs (18) and plan.rs (7): storage, dedup, compression, 1 MB skip, per-file count and age, prune by age and size, shared objects, leftovers, restore and refusals, Recently Deleted prefix rule, bad paths and ids, damaged objects, broken index, usage and clear, editor requests, the diff, folder walking, the per-action byte budget, and one end-to-end test that turns history on in a temp folder and runs save, discard (tracked and untracked) and rollback. Vitest localHistoryModel.test.ts (7), settingsData.test.ts (one case for the four keys).
- Keeping in sync: Label enum (store.rs) and SnapshotLabel (types.ts) and LABELS (localHistoryModel.ts); ranges in plan.rs and settingsData.ts.
- Not done (possible later): checkout/reset --hard/stash hooks, Files panel delete (it uses the Trash), a per-workspace index, persistence of notification history.

## Developer chapter outline: developer/How-Notifications-Work.md

- Why: toasts vanish after a few seconds; errors with details or Undo buttons could be missed.
- How: `toast.show` (src/lib/ui/toast.svelte.ts) records every message in `notifications` (src/lib/notifications/notifications.svelte.ts) before deciding whether to pop up. Pure list ops in notificationModel.ts (cap 200, newest first, unread errors and warnings, button lifetime 30 minutes and once only, Do Not Disturb rule, badge text). Toasts carry `notificationId` so a button run from either place runs once and closes the other. Button lifetime in the list: 2 minutes by default (buttons were written for a toast seen at once), 30 minutes when the producer passes `ToastAction.valid?()` that checks what it acts on is unchanged. New toast buttons (reflog, bisect, auto fetch) should pass `valid` to get the longer window. Old or used buttons drop their closures so the list does not hold what they captured (an Undo's patch).
- New toast kind "warning" (`toast.warning`), amber border, 6 s.
- Mermaid idea (flowchart): toast.show -> notifications.record -> popsUp? -> yes: toast on screen / no (DND, non-error): only listed; bell badge = unread errors + warnings.
- UI: NotificationBell.svelte in StatusBar.svelte (left of the star). Closes on outside click and Escape. View > Notifications and View > Do Not Disturb (check item, `doNotDisturb` in MenuInputs).
- Setting: `notificationsDoNotDisturb` (default false), mirrored into `notifications.doNotDisturb` by App.svelte (avoids a toast -> settings import cycle).
- Tests: notificationModel.test.ts (12): list ops, button lifetimes, plus toast integration with fake timers.
